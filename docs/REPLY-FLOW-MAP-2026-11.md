## 4-2. `/api/ontology/graph` 신설 vs explore·company-pulse 확장

**신설했습니다** — 단, 같은 컨트롤러(`OntologyController`)에 올려 **권한·가시성 정책을 그대로 물려받게** 했습니다.

이유:
- `explore`는 **한 객체에서 출발하는 계보 조회**라 반환 모양이 다릅니다(객체 1개 + 주변). 전 층 그래프는 노드/엣지 전체가 필요해 확장하면 두 용도가 한 함수에 섞입니다.
- `company-pulse`는 **월별 기여 계산 코어**로 KPI 기여·현황판이 공유합니다. 그래프 때문에 건드리면 두 화면이 같이 흔들립니다.
- 대신 **판정 기준은 재사용**했습니다: 목표 연결 여부는 `GoalActivityLink` + `KeyResult.activityId` + `KeyInitiative.activityId`로 company-pulse와 동일하게 봅니다.

```
GET  /api/ontology/graph?month=YYYY-MM     → { nodes, edges, ghosts, summary }
POST /api/ontology/graph/scan              → 관찰 전이 추출(월 단위, 수동)
POST /api/ontology/graph/deviations/:id/decide  → NORM | FIX | KEEP (+사유)
```
전부 `assertExec`(대표·임원).

## 4-3. 렌더러

**canvas를 택했습니다** (시안과 동일).

- 실측 규모: 노드 **약 180개**(원천 5 + 활동 대분류 14 + KPI·과제 108 + 목표 52 + 기둥 4 + 대표 1), 엣지 **약 250개**. 지금은 SVG도 버팁니다.
- 그런데 활동 열을 **활동 단위로 펼치면 노드가 800개를 넘고**(4-5 참조), P1 애니메이션이 들어오면 매 프레임 수백 개 DOM 속성이 바뀝니다. reactflow는 노드마다 React 컴포넌트를 올리므로 여기서 먼저 막힙니다.
- reactflow는 이미 BPMN 편집기에서 쓰고 있지만 그쪽은 **편집(드래그·연결)**이 목적이고, 흐름 맵은 **읽기 전용 + 애니메이션**이라 요구가 반대입니다.

## 4-5. 핸드오프와 다르게 만든 것 — 활동 열을 "대분류"로 묶었습니다

핸드오프는 활동(Activity) 하나당 노드를 전제했는데, 실데이터에서 불가능했습니다.

```
활동 사전 전체          6,492개 (확정 1,533 · AI 후보 4,959)
최근 30일에 쓰인 활동     811개
상위 20개가 차지하는 일지   10%        ← 긴 꼬리, 대표 활동이 없음
```

활동 단위로 그리면 **점 800개에 라벨이 겹쳐 아무것도 읽히지 않습니다.** 그래서 `Activity.domain`(대분류, 6,491개 활동에 채워져 있음)으로 묶어 **14개 노드**로 그리고, 클릭하면 그 안의 주요 활동으로 내려가게 했습니다. 전이도 대분류 수준(`level: 'DOMAIN'`)으로 셉니다. `ObservedTransition.level`에 `ACTIVITY`를 열어 뒀으니 사전이 정리되면 그때 내려가면 됩니다.

**그리고 이게 더 중요한 발견입니다 — 지금 맵의 진짜 메시지는 "정의 밖 경로"가 아니라 "목표 밖"입니다.**

```
최근 30일 활동        811개
  그중 목표에 연결됨     4개   (0.5%)
  목표 밖              807개
목표 밖 투입 시간      248,610분 ≈ 4,143시간/월
```

반면 **미분류 일지는 0%**입니다(2,697건 중 3건). 즉 "기록이 안 남는 문제"는 이미 해결됐고, 남은 문제는 **기록이 목표에 닿지 않는 것**입니다. 핸드오프 2-1(미분류 일지)은 사실상 빈 기능이 되고, 2-2(목표 밖 활동)가 화면의 중심이 됩니다.

원인은 두 겹입니다.
1. **활동 사전이 과분화**돼 있습니다(73명 회사에 6,492개). AI 채굴이 거의 같은 일을 다른 이름으로 계속 만들어 냅니다.
2. 목표 연결(`GoalActivityLink` 379 + KR 75 + KI 1)이 **오래된 활동**을 가리켜, 이번 달 실제로 쓰인 활동과 거의 만나지 않습니다.

→ **P1(애니메이션)보다 활동 사전 정리·병합이 먼저입니다.** 사전이 정리되지 않으면 흐르는 점을 아무리 예쁘게 그려도 가리키는 대상이 틀립니다.

```

(정의된 길 = 같은 프로세스 템플릿에서 이웃한 태스크의 대분류 쌍, 98쌍 사전 생성)
```

빈도 상위 정의 밖 경로:

| 경로 | 건수 / 분모 | 비고 |
|---|---|---|

| 연구개발 → 생산-조립 | 23 / 182 | |
| 연구개발 → 구매·자재 | 16 / 182 | 간격 중앙값 **1일** |
| 품질 → 생산-조립 | 16 / 235 | |

각 경로에 **근거 대상(금형·부품명)** 과 샘플 일지 id를 함께 저장했고, 화면에서 **규범을 고친다 / 현실을 고친다 / 그냥 둔다**(그냥 둔다는 사유 필수)를 고르면 `DeviationDecision`에 남습니다. 개인 이름은 어디에도 나오지 않습니다.

## 4-7. 지켜야 할 것 — 구현에 어떻게 반영했나

| 원칙 | 구현 |
|---|---|
| 집계로만, 개인 이름은 건을 열 때만 | 전이는 대분류 쌍 + 건수만 저장. `sampleCases`에 대상명·일지 id만 담고 작성자는 담지 않음 |
| AI 추정은 후보층, 판단에 쓰지 않음 | 활동 `status=AUTO`가 과반인 대분류는 **점선**. 화면에 "후보층 — 판단에 쓰지 않습니다" 고정 문구 |
| 근거를 붙인다 | 정의 밖 경로마다 근거 대상 3개 표시, 간격 중앙값·공백 비율 표시 |
| 알림 폭탄 금지 | 스캔은 **수동 실행만**(자동 알림 없음). 주간 대표 안건 편입은 P1에서 |
| 시스템 밖 처리 추정 | 전이 단위 `offHoursRatio`(3일 넘게 빈 비율). 50% 넘으면 "메신저·전화로 처리됐을 수 있습니다" 안내. **사람 단위 추정 없음** |

## 4-8. 되돌려 묻고 싶은 것

1. **활동 사전 정리를 P1보다 먼저 할까요?** 6,492개 → 수백 개로 병합하는 작업입니다. AI 병합 후보 제시 + 사람 확정 방식이면 1~2주. 이게 없으면 맵의 해상도가 올라가지 않습니다.
2. **"정의된 길"의 기준**을 프로세스 템플릿만으로 볼지, **같은 목표에 함께 연결된 활동 쌍**도 정의된 것으로 볼지. 지금은 템플릿만 기준이라 정의 밖이 과대 집계될 수 있습니다.
3. 결정(`DeviationDecision`)을 **관리자 시험지 출제 재료**로 넘기는 연결은 P1에 포함할까요, 시험지 쪽 세션과 맞출까요.
4. 핸드오프 1.5의 "결정 로그"와 `DeviationDecision`을 **한 테이블로 합칠지** — 지금은 분리돼 있습니다. 합칠 거면 스키마를 알려 주세요.
