# WorkWork 전체 구성·균형 정리 — 운영 고리 기준 (2026-10-27)

> 목적: 기능을 하나씩 붙여 온 결과를 사업 설명서("중소 제조기업 운영 플랫폼", 2026-10-23)의 취지 위에 올려놓고 전체 구성과 균형을 보기 위한 정리. 대표(홍정수) 요청으로 작성, 대표 전용 메뉴 설계의 근거 문서.

## 1. 취지 — 하나의 운영 고리

설명서의 문장: "대표의 목표가 현장 데이터와 매일 맞물려 돌고, 관리자가 수치에 근거해 결정하며, 노하우가 사람과 함께 떠나지 않는다."

이것은 여섯 단계가 도는 고리이고, 고리 전체의 맞물린 정도를 재는 일곱째 층이 있다.

```
① 목표 세우기 → ② 책임 나누기 → ③ 실행·기록 → ④ 현실 관찰(데이터) → ⑤ 판단 → ⑥ 축적(지식·온톨로지) → ①
                                   ⑦ 완성도·플랫폼 (고리 전체를 측정, 구독 등급의 근거)
```

설명서의 5계층과의 대응: ① ②=계층 5(어젠다·FlowDesk), ③=실행 기록, ④=계층 1·2(현장 연결·기록 시스템), ⑤=계층 4(관리자 시험지), ⑥=계층 3(조직도 축 온톨로지·암묵지 카드·실행 관찰), ⑦=사업 모델 2·3단계(완성도 등급·반출 가능).

## 2. 단계별 취지와 구현된 기능

| 단계 | 취지 (설명서) | 구현된 기능 (2026-10-27 기준) | 상태 |
|---|---|---|---|
| ① 목표 | 대표는 한 문장과 가중치만 정한다 | 경영 어젠다(AI 항목 초안·되묻는 질문·재정리) `/okr/agenda`, 정성 목표(OKR) 입력·조회, 정량 목표(팀 KPI) 입력·조회, 중점 추진 과제, 경영지시(등록·목록·전략 통일성), 전략 정렬 지도, 전사 목표 현황 | 충분. 단, 같은 일을 하는 입구가 4개(어젠다·OKR·중점과제·경영지시) |
| ② 책임 나누기 | 어젠다를 맡는 행위로 실행 조직이 그려진다 | 클레임 지도(항목×팀) → 대표 승인 시 팀 Objective "{year} 경영 어젠다" 아래 KR 자동 생성·담당 배정, KPI 담당 배정, 조직 책임자(OrgUnit.managerId), 팀 과제 관리 | 방금 생김 — 실사용 0건 (어젠다 1건 초안) |

## 3. 균형 진단

- **무게 중심이 ③에 있다.** 설명서가 "기본 반찬"이라 부른 기록 층(결재·신청·일지)이 가장 크고, 수익 층이라 부른 ⑤ 판단이 가장 작다. 최근 2주(10/8~10/27) 개발로 ④⑤⑥⑦의 뼈대는 모두 생겼지만 안에 든 데이터가 적어 고리가 아직 한 바퀴 돌지 않았다.
- **맞물림이 코드로 이어진 곳**: 일지→KPI(분류), 매뉴얼→프로세스→활동, KPI→데이터(바인딩), 어젠다→KR, 암묵지 카드→프로세스 인스턴스 화면, 시험지→KPI 데이터, 계기판이 전부 집계.
- **끊긴 곳(섬)**: 경영지시·회의록·설비투자·업무 요청. 설명서 기준으로 경영지시는 어젠다의 하위, 회의록은 판단 로그, 설비투자는 KPI 위협에 대한 대응, 업무 요청은 프로세스의 협조 단계여야 한다.
- **입구 중복**: ① 목표 입구 4개, ④ 수치 화면 5개(리포트·기여·현황판·데이터AI·통계). 사용자는 어디서 시작할지 모른다.

화면 수 분포(대략): ③ 실행·기록 27 / ① 목표 13 / ⑥ 축적 11 / ④ 관찰 10 / ⑤ 판단 9 / ⑦ 플랫폼 9.

## 4. 이 흐름대로 묶은 대표 전용 메뉴 (안, 6묶음)

구성원 메뉴는 그대로 두고 대표 로그인에만 적용. 기존 메뉴와 헤더 토글로 전환. 신규 개발은 0번 한 화면뿐이고 나머지는 재배치.

| # | 묶음 | 포함 |
|---|---|---|
| 0 | **대표 홈 — 결정할 것** (신규) | 클레임 승인·시험지 확정·결재·투자위 대기 건수, 미클레임 어젠다 항목(붉게), 자기신고≠데이터 KPI, 완성도 점수·등급, 이번 주 암묵지 카드 |
| 1 | **목표와 책임** | 어젠다·클레임 / 전사 목표 현황 / 전략 정렬 지도 / KPI·OKR 조회 / 중점과제 / 경영지시 |
| 2 | **현실(데이터)** | KPI 실적·데이터 연결 / 팀 KPI 리포트 / 기여 분석 / 실행 현황판 / 통계·데이터 AI |
| 3 | **판단** | 관리자 시험지 / 결재하기 / 설비투자 / 품의·전표 / 회의록 |
| 4 | **실행과 축적** | 프로세스(대시보드·템플릿·매뉴얼→프로세스) / 매뉴얼·암묵지 카드 / 활동 지도·조감도·탐색기 / 일지 통계·랭킹 |
| 5 | **플랫폼** | 완성도 계기판 / 회사 설정·온보딩·반출 / 조직·구성원·기준정보·도구 |
| + | **내 일** (홈 하단 바로가기) | 일지 작성, 내 할 일, 올린 결재, 신청 |

기존 메뉴 → 대표 메뉴 대응: 업무일지→2·4·내 일 / 목표관리→1·2·3·내 일 / 결재·업무 요청·신청→3·2·내 일 / 경영지시→1 / 매뉴얼→4 / 프로세스 관리→4·2·5·내 일 / 설비투자·품의서·전표·회의록→3 / 데이터 AI→2 / 관리→5.

## 5. 정리에서 나오는 다음 할 일 (우선순위)

1. **고리를 한 바퀴 돌리기(운영)**: 어젠다 공개 → 클레임 → KR → 데이터 연결 → 시험지 → 카드 확인까지 실제 사용. 선결: 생산팀 조직 책임자 지정, Odoo 읽기 전용 계정.
2. **섬 연결(개발)**: 경영지시→어젠다 항목, 회의록→결정 로그, 설비투자→KPI 위협, 업무 요청→프로세스 협조.
3. **입구 통합(개발)**: 목표 입구 4개 → 어젠다로 수렴, 수치 화면 5개 → "현실" 한 묶음.
4. **대표 홈 1화면 + 대표 메뉴(개발)**.

권장 구현 순서: 4 → 2 → 3 (1은 병행 운영).

## 부록 — 현재 메뉴 전체 (2026-10-27)

- 업무일지: 작성, 조회, 주간 리포트, 업무 현황, 지식 정리 랭킹, 업무 평가 리포트, AI 분석, 내 일지 KPI 분류
- 목표관리: 입력 가이드, 경영 어젠다·클레임, 내 업무 과제, 전사 목표 현황, OKR 입력/조회, 팀 KPI 입력, KPI 실적 입력(수동·데이터 연결), 팀 KPI 조회, 팀 KPI 리포트, 관리자 시험지, 중점 추진 과제, 팀 과제 관리
- 결재: 올리기, 하기, 올린 결재, 통계 · 업무 요청: 요청, 받은, 보낸, 통계
- 신청: 법인차량, 사용 전후 등록, 경비실 현황, 물류 배차, 근태 신청/리포트/OT 검증/입출입, 출장
- 경영지시: 등록, 목록, 전략 통일성 · 매뉴얼: 내 매뉴얼 입력, 조회, 암묵지 카드, 입력 현황(전사), 총무 비상연락망
- 프로세스 관리: 새 프로세스, 내 할 일, 참여, 대시보드, 활동 지도, 전략 정렬 지도, 조감도, 온톨로지 탐색기, KPI 기여 분석, 실행 현황판, 완성도 계기판, 템플릿, 매뉴얼로 프로세스 만들기
- 회의록 · 설비투자: 제안, 사전 검토, 포트폴리오, 위원회, 실행·사후검증, 품의서, 전표 · 데이터 AI: 수치 분석, 업무 자료 분석
- 관리: 조직, 구성원, 휴일, 차량, 기준정보, 변경 이력, 시스템 도구, 회사 설정·온보딩·데이터
